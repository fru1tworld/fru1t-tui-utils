# diff-tui

테스트 파일을 기본으로 숨기는 Git diff TUI입니다. Files에서 파일을 고르면 옆에 변경 전후 코드를 좌우로 표시합니다. `v`로 통합 보기와 전환할 수 있습니다.

Files에서는 디렉터리 트리와 코드 미리보기를 함께 표시합니다. `Tab`이나 파일에서 `Enter`를 누르면 Files를 숨기고 코드가 전체 폭을 사용합니다. 다시 `Tab`을 누르면 트리의 선택과 펼침 상태를 유지한 채 목록과 미리보기로 돌아옵니다.

긴 경로와 파일명은 생략 없이 줄바꿈합니다. 하위 디렉터리만 하나 있는 경로는 한 줄로 묶습니다. 좁은 터미널에서는 Files와 미리보기를 위아래로 배치합니다.

코드 패널에서는 `diff --git`, `index`, `---`, `+++` 파일 헤더를 숨깁니다. 변경 구간과 코드, 바이너리나 파일 권한 변경 요약은 표시합니다.

## 설치와 실행

utils 루트에서 설치합니다.

```sh
cargo install --path diff-tui --locked
```

zsh(Oh My Zsh)에서 브랜치 이름을 `Tab`으로 자동 완성하려면:

```sh
mkdir -p ~/.oh-my-zsh/custom/completions
cp diff-tui/completions/_diff-tui ~/.oh-my-zsh/custom/completions/
```

비교하려는 Git 저장소에서 실행합니다.

```sh
diff-tui                    # HEAD와 현재 작업 폴더 비교, staged + unstaged
diff-tui main               # main과 현재 HEAD의 커밋된 상태 비교
diff-tui main feature       # 두 브랜치의 최종 상태 비교
diff-tui --unified          # 통합 보기로 시작
diff-tui --unstaged         # git diff와 같은 비교
diff-tui --staged           # git diff --cached와 같은 비교
diff-tui -C /path/to/repo    # 다른 저장소 지정
diff-tui --show-tests       # 테스트도 표시한 채 시작
```

설치 없이 utils 루트에서 실행할 수도 있습니다.

```sh
cargo run -p diff-tui -- -C /path/to/repo
cargo run -p diff-tui -- -C /path/to/repo main feature
```

비교 중인 저장소에 checkout, fetch, stage 작업을 수행하지 않습니다. 원격 브랜치는 로컬에 있는 remote-tracking ref를 사용합니다. 현재 변경 모드는 Git이 추적하는 파일을 대상으로 하며, untracked 파일은 포함하지 않습니다.

## 키 조작

| 키 | 동작 |
| --- | --- |
| `v` | 좌우 비교 / 통합 보기 전환 |
| `i` | 공통 들여쓰기 축소 / 원래 들여쓰기 전환 |
| `I` (`Shift-i`) | 들여쓰기 가이드 표시 전환 |
| `W` (`Shift-w`) | 공백 변경 무시 전환, 기본 꺼짐 |
| `Tab` | Files와 미리보기 / 코드 전체 화면 전환 |
| `Enter` | 파일 열기 / 디렉터리 펼치기 또는 접기 |
| Files에서 오른쪽 / `l` | 디렉터리 펼치기 / 하위 항목으로 이동 / 파일 열기 |
| Files에서 왼쪽 / `h` | 디렉터리 접기 / 상위 디렉터리로 이동 |
| `j` / `k`, 위 / 아래 | 현재 패널에서 이동 |
| `n` / `p` | 다음 / 이전 파일 |
| `PageDown` / `PageUp` | 한 화면 아래 / 위 |
| `Ctrl-d` / `Ctrl-u` | 반 화면 아래 / 위 |
| `g` / `G` | 처음 / 끝 |
| 코드 비교에서 왼쪽 / 오른쪽 | 화면보다 긴 토큰을 가로 스크롤, 줄 번호는 고정 |
| `[` / `]` | 이전 / 다음 변경 묶음 |
| `t` | 테스트 표시 전환 |
| `/` | 파일 경로 검색, `Enter`로 유지, `Esc`로 초기화 |
| `b` | 비교할 FROM 브랜치, TO 브랜치를 차례로 선택 |
| `w` | HEAD와 현재 작업 폴더 비교 |
| `s` / `u` | staged / unstaged 변경 비교 |
| `r` | 파일 목록과 diff 새로고침 |
| `?` | 도움말 |
| `q`, `Ctrl-c` | 종료 |

브랜치 선택 창에서는 이름을 입력해 검색하고 위 / 아래 키와 `Enter`로 선택합니다. `Esc`로 선택을 취소합니다.

1초 간격으로 파일 목록과 선택한 파일의 변경을 백그라운드에서 확인합니다. 내용이 바뀌면 자동으로 갱신하고, 선택한 파일과 스크롤 위치, 검색 조건을 유지합니다. 선택한 파일이 변경 목록에서 사라지면 가까운 파일을 선택합니다. `r`로 즉시 새로고침할 수도 있습니다. Git 조회가 1초보다 오래 걸리면 조회가 끝난 뒤 다음 확인을 시작하며, 조회를 중복 실행하지 않습니다.

브랜치 비교도 로컬 브랜치와 remote-tracking ref의 변경을 반영합니다. 원격 서버에서 커밋을 가져오는 fetch는 자동 실행하지 않습니다.

## 구문 강조와 줄바꿈

두 보기 모두 `syntect`와 `two-face`의 구문 정의로 강조합니다. Rust, Kotlin, Scala, Java, JavaScript, TypeScript, TSX, Python, Go, PHP, Ruby, C/C++, C#, Swift, 셸, JSON, YAML, TOML, SQL, HTML/CSS 등 다양한 언어를 지원합니다. 파일명과 확장자, 첫 줄로 판별하며, 알 수 없는 형식은 일반 텍스트로 표시합니다. [지원 구문 목록](https://docs.rs/two-face/0.5.2/two_face/syntax/index.html)

변경 전후 원문을 각각 읽어 여러 줄 주석과 문자열의 문맥을 유지합니다. 색칠한 결과는 파일을 선택하거나 변경 내용과 원문이 바뀌었을 때 계산하고, 화면 폭이 바뀌면 줄바꿈만 다시 계산합니다. LSP와 언어별 실행 환경은 필요하지 않습니다. 언어의 세부 버전 판별이나 타입 분석은 수행하지 않습니다.

`()`, `[]`, `{}`는 중첩 깊이에 따라 여섯 색을 순환하며 짝을 같은 색으로 표시합니다. 구문 정의에서 문자열이나 주석으로 판별한 영역과 일반 텍스트 파일에는 적용하지 않습니다.

자동 줄바꿈은 식별자, 숫자, 따옴표로 묶인 문자열, 연산자의 경계를 우선합니다. 색상이 바뀌는 위치와 토큰 경계는 별도로 취급합니다. 토큰 중간이나 한글, 결합 문자, 이모지의 문자 묶음을 자르지 않습니다. 한 토큰이 패널보다 길면 가로 스크롤로 확인합니다. 이는 AST나 의미 분석을 사용하는 줄바꿈이 아니라 어휘 경계에 따른 줄바꿈입니다.

삭제와 추가 행은 내용이 비슷한 줄끼리 순서를 유지하며 정렬합니다. 대응하는 줄에서 바뀐 단어는 진한 배경색과 굵은 글씨로 강조합니다. 큰 변경 묶음은 정렬 계산량과 시간을 제한하며, 한도를 넘으면 순서대로 짝짓습니다. 양쪽 줄바꿈 수가 다르면 짧은 쪽을 빈 행으로 채웁니다. 보기 전환과 창 크기 변경 시 같은 변경 행을 기준으로 스크롤 위치를 유지합니다. 삭제와 추가는 배경색과 `-`, `+`로 구분하고, 코드 글자색은 언어 구문 강조에 사용합니다.

변경 구간마다 양쪽에 공통으로 있는 앞쪽 공백을 화면에서 줄입니다. 줄인 칸 수는 구간 제목의 `indent -N`으로 표시하며, `i`로 원래 들여쓰기를 볼 수 있습니다. 들여쓰기 가이드는 4칸 간격으로 표시하고 `I`로 끌 수 있습니다. 원문과 실제 들여쓰기 차이는 유지합니다.

`W`는 Git의 `--ignore-all-space`로 코드 diff를 다시 읽습니다. 파일 목록은 유지하며 공백 차이만 있는 파일은 빈 비교로 표시합니다. 문자열 안의 공백도 구별하지 않는 Git 옵션이므로 기본은 꺼져 있습니다. 자동 갱신과 비교 모드 전환에도 선택한 옵션을 유지합니다.

## 테스트 판별

파일의 경로와 이름으로 판별합니다.

- 폴더: `test`, `tests`, `__tests__`, `__snapshots__`, `testdata`, `testFixtures`, `androidTest`, `integrationTest`, `commonTest`, `e2e`, `spec` 등.
- 파일명: `*.test.*`, `*.spec.*`, `*_test.go`, Python의 `test_*.py`와 `*_test.py`, JVM의 `*Test`, `*Tests`, `*Spec` 클래스 파일.
- 테스트 폴더 안의 리소스도 함께 숨깁니다. 삭제된 파일도 같은 규칙을 적용합니다.
- 운영 경로와 테스트 경로 사이의 이동은 표시합니다.

소스 파일 안에 함께 작성한 테스트, 예를 들어 Rust의 `#[cfg(test)]` 모듈은 제거하지 않습니다. 별도 테스트 소스셋 등 위 규칙에 없는 경로는 표시될 수 있고, 관례와 이름이 겹치는 운영 파일은 숨겨질 수 있습니다. 숨긴 파일 수는 상단에 표시되며 `t`로 전체 파일을 확인할 수 있습니다.

## 개발

```sh
cargo fmt --all -- --check
cargo clippy -p diff-tui --all-targets -- -D warnings
cargo test -p diff-tui
```

테스트는 임시 Git 저장소에서 현재 변경, staged, unstaged, 분기된 두 브랜치, 첫 커밋 이전 상태, 이름 변경, 삭제, 바이너리 파일과 강조에 쓰는 원문을 검증합니다. 좌우 정렬, 통합 보기 순서, 토큰 줄바꿈, Unicode, 여러 줄 주석과 주요 언어의 구문 정의도 검사합니다.
